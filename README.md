# luci-app-exit-route-openwrt-package

A LuCI application for managing exit routing in an OpenWrt mesh built with
`openwrt-mesh-builder`. It provides global selection between automatic exit
routing, configured IPIP exits, and WAN, plus per-device IPv4 routing policies
and route status. The package is a frontend for an existing `exit-route.sh`
service; it does not install that service.

## Описание

Приложение LuCI для управления выходной маршрутизацией в OpenWrt mesh-сети,
развёрнутой с помощью `openwrt-mesh-builder`. Интерфейс позволяет выбирать
общий маршрут автоматически, через настроенный IPIP-выход или WAN, задавать
отдельные правила IPv4-маршрутизации для устройств и просматривать состояние
выходов. Пакет представляет собой интерфейс к уже установленному сервису
`exit-route.sh` и сам этот сервис не устанавливает.

Проект находится в разработке. Реализованы интерфейс и упаковка LuCI,
но перед эксплуатацией необходима интеграционная проверка с настоящими
`fw4`, `netifd`, Babel и конфигурацией mesh-builder на маршрутизаторе.

## С чего начать

1. Убедитесь, что на маршрутизаторе развёрнут совместимый
   [`openwrt-mesh-builder`](https://github.com/karen07/openwrt-mesh-builder)
   с сервисом `/etc/scripts/exit-route.sh`.
1. Проверьте [требования](#%D1%82%D1%80%D0%B5%D0%B1%D0%BE%D0%B2%D0%B0%D0%BD%D0%B8%D1%8F) и
   [соберите LuCI-пакет](#%D1%81%D0%B1%D0%BE%D1%80%D0%BA%D0%B0-%D0%B8-%D1%83%D1%81%D1%82%D0%B0%D0%BD%D0%BE%D0%B2%D0%BA%D0%B0).

## Возможности

- **Общий маршрут:** режим `AUTO`, конкретный IPIP-выход или `WAN`.
- **Состояние выходов:** наличие маршрута Babel, название IPIP-туннеля
  и интерфейс установленного маршрута.
- **Проверка WAN:** статус `network.interface.wan` через `ubus` и маршрут
  по умолчанию через соответствующий интерфейс в таблице `main`.
- **Маршрутизация устройств:** объединённый список DHCP-аренд, правил
  `routing_rules` из развёртывания mesh-builder и ручных переопределений LuCI.
- **Режимы для устройства:** использовать общий маршрут, WAN, конкретный
  выход или `Split via <exit>`.
- **Добавление по IPv4:** можно задать адрес вручную, даже если устройства
  нет в списке DHCP-аренд.
- **Возврат исходного правила:** `Restore` удаляет ручное переопределение
  и вновь показывает правило из конфигурации развёртывания.
- **Локализация:** английские исходные строки интерфейса и перевод на русский
  через стандартный механизм LuCI gettext.

Состояние обновляется автоматически с интервалом около пяти секунд.

## Требования

Пакет рассчитан на **совместимую версию** `openwrt-mesh-builder`, которая
устанавливает и настраивает:

- `/etc/scripts/exit-route.sh` с командами `status`, `set`, `device-list`,
  `device-set` и `device-del`;
- выходы IPIP и маршруты Babel;
- конфигурацию firewall4 (`fw4`) и правила маркировки пакетов `MARK`;
- сгенерированные policy routing tables для доступных выходов.

В архиве этого репозитория **нет реализации `exit-route.sh`**. Установка
одного LuCI-пакета не создаёт сервис и не расширяет старую версию mesh-builder
необходимыми командами. Требуется соответствующая обновлённая конфигурация
из проекта mesh-builder.

Зависимость, объявленная в LuCI Makefile: `luci-base`. Это зависимость
пакета для сборки, а не полный список компонентов, нужных для работы всей
mesh-системы.

## Сборка и установка

Добавьте каталог пакета в дерево сборки OpenWrt:

```text
openwrt/
`-- package/
    `-- luci-app-exit-route/
        |-- Makefile
        |-- htdocs/
        |-- root/
        `-- po/
```

В конфигурации сборки включите пакет:

```text
CONFIG_PACKAGE_luci-app-exit-route=y
```

При необходимости включите `luci-i18n-exit-route-ru` для русского интерфейса.
Соберите прошивку либо пакет обычными средствами сборочной системы OpenWrt.
Перед использованием установите совместимые скрипты и конфигурацию
`openwrt-mesh-builder` на маршрутизатор.

После установки интерфейс находится в **Network -> Exit Route**.

## Использование

### Командный интерфейс сервиса

Команды ниже реализует **внешний** `exit-route.sh` из совместимой сборки
mesh-builder; они не являются исполняемыми файлами данного LuCI-пакета:

```sh
/etc/scripts/exit-route.sh status
/etc/scripts/exit-route.sh set AUTO
/etc/scripts/exit-route.sh set FR2
/etc/scripts/exit-route.sh set WAN
/etc/scripts/exit-route.sh device-list
/etc/scripts/exit-route.sh device-set 10.101.1.77 exit FR2
/etc/scripts/exit-route.sh device-set 10.101.1.77 split FR1
/etc/scripts/exit-route.sh device-set 10.101.1.77 wan -
/etc/scripts/exit-route.sh device-set 10.101.1.77 default -
/etc/scripts/exit-route.sh device-del 10.101.1.77
```

Названия выходов (`FR1`, `FR2`) и IPv4-адрес служат примерами: используйте
значения своей конфигурации. Таблицы выходов `10001+` создаёт генератор
mesh-builder, а не UI.

## Архитектура и реализация

### Как работает маршрутизация

LuCI вызывает `/etc/scripts/exit-route.sh` через `fs.exec`, а разрешения
для чтения и изменения состояния задаются в `rpcd` ACL.

#### Общий маршрут

- `AUTO` - автоматический выбор доступного выхода согласно его приоритету.
- `<EXIT>` (например, `FR2`) - выбор конкретного выхода.
- `WAN` - использование основной таблицы маршрутизации вместо mesh-выхода.

Режим сохраняется в `/var/run/exit-route` и **сбрасывается на `AUTO` после
перезагрузки**. Важно различать выбранный режим и фактически активный выход:
при недоступности выбранного выхода сервис может отключать общий exit route.

#### Правила для устройств

Для устройства можно выбрать:

| Режим | Поведение |
| --- | --- |
| `Use global route` | Явно следовать общей политике маршрутизации. |
| `WAN` | Направлять трафик через WAN. |
| `<EXIT>` | Использовать выбранный выход mesh. |
| `Split via <EXIT>` | Применить split-политику через указанный выход. |
| `Restore` | Удалить переопределение LuCI и восстановить видимость правила из развёртывания. |

При изменении правила сервис записывает UCI-секции firewall и перезагружает
firewall. Используются те же правила маркировки `fw4 MARK` и таблицы policy
routing, что и у mesh-builder; отдельная параллельная схема `ip rule` для
LuCI не создаётся.

**`Use global route` и `Restore` - разные действия.** Первое задаёт явное
переопределение правила устройства, второе убирает его, позволяя снова
действовать исходной политике из `routing_rules`.

Переопределения находятся в `/etc/config/firewall` и обычно сохраняются
после перезагрузки. Однако повторное развёртывание mesh-конфигурации может
перезаписать firewall и удалить эти настройки.

### Что означает статус доступности

Для mesh-выхода проверяется наличие маршрута-объявления Babel. Это
**не** отдельный тест работоспособности IPIP-туннеля и не проверка выхода
в интернет.

Для WAN проверяются состояние интерфейса `wan`, его `l3_device` и наличие
маршрута IPv4 по умолчанию через это устройство в таблице `main`.
**Пинг или HTTP-запрос к внешнему адресу не выполняется.**

## Ограничения

- Обрабатывается **только IPv4-трафик**, входящий через зону `lan`, как в
  исходной схеме `routing_rules` mesh-builder.
- Политики IPv6, DNS и другие входящие зоны в текущем варианте не охвачены.
- Работа зависит от конкретного контракта команд и формата вывода
  `exit-route.sh`; несовместимая версия сервиса приведёт к ошибкам интерфейса.
- Для практического использования необходимы интеграционные тесты на
  реальном OpenWrt с `fw4`, `netifd` и Babel. Наличие исходников интерфейса
  не означает завершённой проверки всей системы.
